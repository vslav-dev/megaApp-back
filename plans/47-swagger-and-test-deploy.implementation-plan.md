# Swagger только на тесте + возврат тестового деплоя — бэкенд (основной план)

Парный план фронтенда: [47-swagger-and-test-deploy.implementation-plan.md](../../megaapp-front/plans/47-swagger-and-test-deploy.implementation-plan.md).

## Описание

- Вернуть Swagger (был на Node/Fastify, при переезде на Go пропал).
- Swagger есть только в тестовой сборке. В прод-бинарнике его нет вообще: ни спеки, ни страницы UI, ни роута.
- Вернуть тестовый деплой: push в `develop` → `megatest`, push в `release` → `megaback`.

## Как было

- Node: `@fastify/swagger` + `@fastify/swagger-ui`, роут `/swagger` регистрировался безусловно, защиты не было, в `servers` только dev-адрес.
- Go: Swagger отсутствует. Деплой-воркфлоу `deploy-test.yml` удалён 19.07.2026 (`56fb47b`), остался только `deploy-prod.yml`. Сервер `megatest` на VPS выключен.
- `develop` в обоих репозиториях отстаёт от `release` (0 коммитов впереди), то есть тестовая ветка свободна.

## Решение

### Как Swagger пропадает с прода

- Go build tag `swagger`. Файл с `go:embed` спеки и роутами компилируется только с тегом. Без тега подключается пустая заглушка регистрации.
- Прод-бинарник собирается без тега → в нём нет ни строки спеки, ни HTML UI. Выключать и защищать нечего.
- Альтернативы отвергнуты: проверка `APP_ENV` в рантайме (код и спека остаются в бинарнике, одна ошибка в `.env` открывает документацию), basic auth / allowlist (лишняя поверхность на проде).
- Гарантия: тест `!swagger` (идёт в `go test ./...` прод-воркфлоу) проверяет 404 на роутах документации.

### Спека (вариант 1: вручную)

- Один файл `openapi.yaml` рядом с роутером, `go:embed` только в тегированном файле.
- UI — Swagger UI из CDN, отдаётся с того же origin, что и API. Роуты `/api/swagger` и `/api/swagger/openapi.yaml`: nginx проксирует на бэкенд только `/api`, лишний `location` не нужен.
- Авторизация — cookie-сессия. Логин через `POST /api/auth/login` прямо в UI ставит cookie, «Try it out» проходит same-origin проверку мутирующих методов.
- В спеку не входят: `/api/ws` (WebSocket), `/api/ingest/*` (ключи расширений), `/api/debug/*` и `/api/lab/*` (только с самого сервера).
- Защита от рассинхрона: тестовый обход всех роутов chi сверяет их со спекой в обе стороны (новый публичный роут без записи в спеке или запись про удалённый роут → тест красный).
- Формы ответов food-чтений и вложенных объектов описаны как «объект»: точные схемы не дублируются, источник правды — код.

### Деплой

- Общий воркфлоу получил параметр тегов сборки. Он влияет и на `go test`, и на `go build`: тестовая сборка гоняет тесты со Swagger, прод — без.
- `deploy-test.yml` возвращён: `develop` → сервис `megatest`, путь `/root/megatest`, тег `swagger`.
- `deploy-prod.yml` без изменений: `release` → `megaback`, без тегов.
- Фронт: возвращён `deploy-test.yml` (`develop`, конфигурация `test`, `/var/www/megatest`).

### Рабочий процесс

- Работа идёт в `develop` → автодеплой на тест, там смотрим Swagger и проверяем.
- Готовое вливается в `release` → автодеплой на прод без Swagger.

## Находки после ревью (v-review:claude, 28.10.2026)

### Баги
1. Проверка «спека = роуты» гоняется только в тестовой сборке
   - **Класс:** B
   - **Важность:** стоит поправить
   - **Как сейчас работает:** воркфлоу запускает `go test` с теми же тегами, что и сборка. Прод-деплой (`release`) идёт без тега, значит тест сверки спеки с роутами там не выполняется.
   - **Что не так:** коммит напрямую в `release` с новым роутом без записи в спеке проходит CI. Спека тихо устаревает и ломает тестовый деплой только при следующем пуше в `develop`.
   - **Как поправить:** тесты всегда гонять в обоих вариантах (без тега и с `swagger`), а тег оставить только для сборки артефакта.
   - **Как будет работать после правки:** любой деплой, в том числе прод, краснеет при расхождении спеки и роутов, а прод-бинарник по-прежнему собирается без Swagger.
   - **Объём правки:** малый — шаг тестов в `deploy-backend.yml`.
   - **Рекомендация:** чинить — класс B, стоит поправить, правка малая

2. В спеке у `regenerate-image` не описаны коды 404, 409, 429
   - **Класс:** B
   - **Важность:** мелочь, но стоит поправить
   - **Как сейчас работает:** описаны только 202 и 403.
   - **Что не так:** сервис отвечает 404 (товар не найден), 409 (генерация отключена), 429 (очередь полна). В Swagger их не видно.
   - **Как поправить:** добавить эти три ответа в операцию.
   - **Как будет работать после правки:** документация совпадает с поведением.
   - **Объём правки:** малый — один блок в `openapi.yaml`.
   - **Рекомендация:** чинить — класс B, мелочь, правка малая

3. Скрипты Swagger UI грузятся с CDN без проверки целостности
   - **Класс:** B
   - **Важность:** мелочь, но стоит поправить
   - **Как сейчас работает:** страница на том же origin, что и API, подключает скрипт с `unpkg.com` без `integrity`.
   - **Что не так:** подмена файла на CDN выполнит код с доступом к API под сессией открывшего страницу. Вероятность низкая, сервер тестовый, но данные там реальные копии.
   - **Как поправить:** добавить `integrity` и `crossorigin` для обоих файлов.
   - **Как будет работать после правки:** изменённый файл браузер не выполнит.
   - **Объём правки:** малый — атрибуты в странице `swagger.go`.
   - **Рекомендация:** чинить — класс B, мелочь, правка малая

4. В «Как было» утверждение про `megatest` не проверено
   - **Класс:** B
   - **Важность:** мелочь, но стоит поправить
   - **Как сейчас работает:** план пишет «сервер `megatest` на VPS выключен».
   - **Что не так:** это слова владельца, на сервере состояние не смотрели. В `SERVERS` юнит `megatest` вообще не описан.
   - **Как поправить:** переформулировать как «по словам владельца выключен, в `SERVERS` не описан, состояние на сервере не проверялось».
   - **Как будет работать после правки:** план не выдаёт предположение за факт.
   - **Объём правки:** малый — одна строка плана.
   - **Рекомендация:** чинить — класс B, мелочь, правка малая

### Архитектура
5. Фронтовый `deploy-test.yml` — копия `deploy-prod.yml`
   - **Класс:** K
   - **Источник:** Claude
   - **Как сейчас работает:** два файла по ~55 строк отличаются тремя значениями: ветка, конфигурация сборки, каталог на сервере.
   - **Что не так:** любая правка деплоя (версия Node, шаги, секреты) делается дважды и со временем расходится. В бэке тот же случай решён общим `deploy-backend.yml`, во фронте до 18.08.2026 был общий `build-and-deploy.yml`, потом его убрали, пока тест не был нужен.
   - **Чистая альтернатива:** один переиспользуемый воркфлоу сборки и выкладки с параметрами «ветка / конфигурация / каталог», `deploy-prod.yml` и `deploy-test.yml` — тонкие обёртки, как в бэке.
   - **Корень:** тестовое окружение возвращается, значит у воркфлоу снова два потребителя и общий кусок должен жить в одном месте.
   - **Как будет работать после правки:** прод и тест выкатываются одним кодом, различаются тремя параметрами.
   - **Объём правки:** средний — новый общий воркфлоу, переписать `deploy-prod.yml` (путь прод-деплоя), `deploy-test.yml`.
   - **Рекомендация:** чинить — класс K, размер не вето

**Замечено рядом (не блокирует):** тест сверки спеки сравнивает только метод и путь, коды ответов и `required` в телах запросов money написаны по хендлерам и тестом не проверяются.

- Находка 1: воркфлоу всегда гоняет `go test` в двух вариантах (без тега и с `swagger`). Тег `build-tags` остался только у сборки артефакта. Это меняет пункт «Деплой» выше: там тесты шли с теми же тегами, что и сборка.

## Тестовое окружение: данные и метрики (28.10.2026)

Тестовый сервер должен быть копией прода на текущий момент, но без метрик и без бэкапов.

### Метрики

- В бэкенде не было способа их выключить: `FLATLINE_BASE_URL` обязателен, тест слал бы метрики в прод-Flatline под тем же ключом сервиса и загрязнял бы прод-графики.
- Отвергнуто: указать мёртвый адрес Flatline. Ошибка пуша каждую минуту, растущий файл очереди, ложные логи.
- Решение: переключатель `METRICS_ENABLED` (по умолчанию включён, прод не меняется). Выключенный: нет отправки и опроса Flatline, нет сэмплера процесса, нет минутной джобы, нет подписок на метрики, нет роута истории. Счётчики остаются в памяти (карта по именам, не растёт). Адрес Flatline при выключенном флаге не требуется.

### Данные на сервере (сделано вручную по поручению владельца)

- `/root/megatest` создан: `data/`, `public/`, `backups/`; `migrations/` и бинарник приезжают деплоем.
- БД: консистентный снимок живой прод-базы (онлайн-копия SQLite, прод открыт только на чтение) в `data/megaapp-test.db`, проверка целостности `ok`.
- Картинки: полная копия `public/` (2436 файлов, как в проде).
- `.env.test`: копия прод-конфигурации с отличиями `APP_ENV=test`, `APP_PORT=3001`, `BACKUP_JOB_ENABLED=false`, `BACKUP_STORAGE_ENABLED=false`, `METRICS_ENABLED=false`. Права 600. Ключи OpenRouter/OpenAI и секрет сессий совпадают с продовыми.
- Телеметрия расширений (`INGEST_*`) оставлена как в проде.
